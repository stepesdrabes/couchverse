# Building the Apple apps

The iPhone/iPad app (`Couchverse`) and the Apple TV app (`Couchverse TV`) are SwiftUI shells over
the shared Rust core (plan sections 7 and 10). Couchverse is open source and built from source:
there is no App Store build, and everything here works with a free Apple ID.

## Prerequisites

- macOS with **Xcode 27** (iOS 27 and tvOS 27 SDKs and simulators). `swift-format` ships with it.
- **Rust** through rustup, with the Apple targets:
  `rustup target add aarch64-apple-ios aarch64-apple-ios-sim aarch64-apple-tvos aarch64-apple-tvos-sim`
  (tvOS is a Tier 2 target with prebuilt standard libraries; no nightly needed).
- A Couchverse server to connect to (`docker compose up db -d` and `make run-backend` for a
  local one; admin/admin).

## Layout

```
clients/apple/
  Couchverse.xcodeproj    two apps and their UI test bundles; folder-synchronized groups, so adding a
                          file never touches the project file
  Config/                 Base.xcconfig (shared), one xcconfig and Info.plist per target,
                          Local.xcconfig.template (copy to the gitignored Local.xcconfig)
  Couchverse/             iOS/iPadOS app entry and assets
  CouchverseTV/           tvOS app entry and assets
  CouchverseUITests/      smoke UI test (iPhone/iPad simulator)
  CouchverseTVUITests/    smoke UI test (Apple TV simulator)
  Packages/
    CouchverseCore        the xcframework, the generated message types, CoreRuntime and the
                          effect executors (HTTP, timers, Keychain, files/user defaults)
    CouchverseDesign      tokens, typography, accent, components, generated strings
    CouchverseFeatures    the screens by feature (Accounts, Onboarding, Settings, Home) and the
                          root the apps show
```

The apps are thin: each creates the runtime (`LiveRuntime.make()`) and shows `CouchverseRoot`.
`CoreRuntime` is the only stateful service; screens read its view models and send events, and own
nothing but presentation state (focus, sheets, a field being typed).

## Build

1. Build the core for Apple once, and again whenever `core/` changes:

   ```sh
   make core-apple
   ```

   This builds the static libraries for iOS, the iOS simulator, tvOS, the tvOS simulator and the
   Mac (for host tests), the `CouchverseCoreFFI.xcframework` and the UniFFI Swift file
   (`Packages/CouchverseCore/Sources/CouchverseCore/FFI/`). Both are build output and gitignored;
   the message types (`Generated/Messages.swift`) and strings are committed and regenerated by
   `make contract`.

2. For a simulator, open `clients/apple/Couchverse.xcodeproj`, pick the `Couchverse` or
   `Couchverse TV` scheme and a simulator, and run. No signing setup is needed.

3. For your own devices, copy `Config/Local.xcconfig.template` to `Config/Local.xcconfig` and set
   `DEVELOPMENT_TEAM` (Xcode > Settings > Accounts shows your team; a free personal team works)
   and a `BUNDLE_ID_ROOT` of your own (`com.yourname.couchverse`: a bundle id is unique across
   all teams, so the default `io.stepes.couchverse` is taken). Both apps share one bundle id, so
   they need one App ID. Leave `EXTENSIONS_ENABLED = NO` with a free team.

From the command line:

```sh
xcodebuild -project clients/apple/Couchverse.xcodeproj -scheme Couchverse \
  -destination 'platform=iOS Simulator,name=iPhone 17' build
xcodebuild -project clients/apple/Couchverse.xcodeproj -scheme 'Couchverse TV' \
  -destination 'platform=tvOS Simulator,name=Apple TV 4K (3rd generation)' build
```

## Test and lint

| Command | What runs |
|---|---|
| `make apple-test` | `CouchverseCore` tests on the Mac (`swift test`: the runtime over the real core with fake executors, the executors themselves), then `CouchverseDesign` and `CouchverseFeatures` tests on an iOS simulator and `CouchverseFeatures` on a tvOS simulator (Swift Testing, plus snapshot tests). |
| `make apple-uitest` | The smoke UI test of each app on a simulator (fresh install, no server needed). |
| `make apple-lint` / `make apple-format` | `swift-format` over every hand-written Swift file (`clients/apple/.swift-format`); CI runs the lint. |

`IOS_SIM` and `TV_SIM` choose the simulators by name (`make apple-test IOS_SIM='iPhone 17 Pro'`).
Design and Features are iOS and tvOS packages, so they build with `xcodebuild -scheme <package>`
inside the package directory, no project needed; only `CouchverseCore` also builds for the Mac.

**Snapshots.** `ScreenSnapshots` renders each key screen from fixture view models
(`Fixtures.swift`) for every load state: on iPhone and TV in English at the default text size and
in Czech at the largest Dynamic Type, and on iPad in English. References are in
`Packages/CouchverseFeatures/Tests/CouchverseFeaturesTests/__Snapshots__`. A missing reference is
recorded on the first run and that run fails, so new screens are reviewed before they are
committed. After an intended visual change, delete the affected references, run `make apple-test`
twice and review the new images. Package tests have no host app, so the screens are drawn with
`Ambience.flat` (no glow, solid instead of glass buttons: a prominent glass button at the largest
text sizes renders nothing without one); `designGallery` draws the glow and glass once.

**UI tests.** The smoke tests launch the apps with `-uiTesting`, which keeps the stores in memory
so every launch is a fresh install. `LiveFlowTests` drive the real flows against a running
server and are skipped unless one is given; they keep the app's stores, so run them in order on
fresh simulators (`xcrun simctl uninstall <device> <bundle id>` and `xcrun simctl keychain
<device> reset` start over):

```sh
export TEST_RUNNER_CV_LIVE_SERVER=192.168.1.5:8080            # what the user types
export TEST_RUNNER_CV_PAIRING_CODE_FILE=/tmp/pairing-code.txt  # the TV writes, the phone reads
export TEST_RUNNER_CV_SCREENSHOTS=/tmp/screens                 # optional
# phone: add the server and sign in as admin/admin
xcodebuild test -project clients/apple/Couchverse.xcodeproj -scheme Couchverse -destination ... \
  -only-testing:CouchverseUITests/LiveFlowTests/test1AddAServerAndSignInWithAPassword
# TV (in the background): add the server, show a pairing code, wait to be approved
xcodebuild test ... -scheme 'Couchverse TV' -only-testing:CouchverseTVUITests/LiveFlowTests/test1AddAServerAndPairFromThePhone &
# phone: approve the TV's code in Settings
xcodebuild test ... -only-testing:CouchverseUITests/LiveFlowTests/test2ApproveTheTVsPairingCode
# TV: add a second profile (nora/couchverse by default), then switch profiles
xcodebuild test ... -only-testing:CouchverseTVUITests/LiveFlowTests/test2AddASecondProfileWithAPassword
xcodebuild test ... -only-testing:CouchverseTVUITests/LiveFlowTests/test3SwitchProfiles
```

`xcrun simctl io <device> recordVideo` captures the profile switch.

## Free personal team limits

Building for your own devices with a free Apple ID works, with these limits (plan 10.9):

- Apps are provisioned for **7 days**: reinstall from Xcode weekly (your data and Keychain stay).
- At most **3 apps** you built can be installed on a device at once.
- New App IDs are limited per week (10); using one bundle id for both apps keeps this to one.
- No App Groups or Keychain Sharing guarantees, so widgets and Top Shelf (later phases) stay off
  behind `EXTENSIONS_ENABLED`; no Associated Domains, so links use the `couchverse://` scheme.
- An Apple TV is installed over Xcode's **wireless pairing**: on the TV open Settings > Remotes and
  Devices > Remote App and Devices, then in Xcode Window > Devices and Simulators pair it.

## Real-device checklist

The simulators cover the flows (see the Phase 3 report); on hardware, also check:

1. **Signing with a free team**: with `Local.xcconfig` filled in, both apps build, install and
   launch on an iPhone and an Apple TV; the 7-day profile appears under Settings > General > VPN &
   Device Management on the phone (trust the developer certificate once).
2. **Wireless pairing to the Apple TV**: the TV shows up in Xcode's devices list, `Couchverse TV`
   installs and runs from Xcode without a cable.
3. **Local network**: on the iPhone, adding a server on the LAN (`192.168.x.y:8080`) shows the
   Local Network permission prompt once and connects after "Allow"; plain http shows the "Not
   encrypted" badge on sign-in and in Settings.
4. **Camera QR scan**: on the phone, Welcome > "Scan a QR code" scans the web's Connect a device
   code and signs in; Settings > "Approve a device" > "Scan the code on the TV" scans the TV's
   pairing QR and shows the approval (the camera permission prompt appears once).
5. **Pairing end to end**: the TV's "Sign in with another device" code is approved from the phone
   and the TV signs in within one polling interval (5 s); an expired code offers a new one.
6. **Who's watching on the TV**: relaunching the TV app opens the picker; focus moves with the
   remote, the focused profile lifts and tints the backdrop, choosing one plays the full
   animation; with Settings > Accessibility > Reduce Motion on, it cross-fades instead.
7. **Keychain persistence across reinstalls**: install over the existing app (the weekly
   free-team refresh) on both devices: servers, accounts and tokens survive, the phone resumes its
   account and the TV opens on "Who's watching?" with every profile signed in. Then delete the
   phone app and install it again: the server list goes with the app (Application Support), the
   tokens stay in the Keychain but nothing refers to them, so the app starts cleanly at Welcome and
   signing in again overwrites them. On the TV, servers and accounts live in user defaults (the
   only storage tvOS guarantees) and tokens in the Keychain; check both survive a night of the TV
   sleeping and the system reclaiming space.
8. **Display language**: switching to Čeština in Settings changes every string at once and
   survives a relaunch (it is saved as the account's preference).
